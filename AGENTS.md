# ClicknTranslate: правила интерфейса

- Сохраняйте существующую сдержанную палитру, пять вкладок и общие поля/кнопки. Подписи и относящиеся к ним настройки должны образовывать понятные группы.
- Для строк галочек во всех пяти вкладках используйте общие высоту и зазор из `src/settings_metrics.py`; сравнивайте фактический шаг строк после отрисовки, включая RTL и масштабирование.
- Для выпадающих списков используйте общий компонент и делегат. Независимые галочки должны явно объяснять результат включения и выключения; не выдавайте их за выбор одного режима.
- У каждого скруглённого окна/списка/подсказки должны сохраняться все четыре угла и рамка. На Windows/Cocoa у прозрачных frameless-поверхностей и в GraphicsProxy сохраняйте альфа-рисование без лишней бинарной QRegion-маски. Для платформенного fallback согласуйте радиус и масштаб маски с рисунком, включая сглаженные граничные пиксели. Не подменяйте исправление исчезающих углов очередным локальным радиусом.
- Проверяйте геометрию промежуточных контейнеров, включая панели захвата: их contentsRect должен вмещать дочерние поля, флаги, подписи, индикаторы и кнопки. Учитывайте QFrame.frameWidth(), minimumSizeHint, sizePolicy и отступы; QSizePolicy.Ignored не должен приводить к пересечению полей фиксированного размера.
- Не очищайте родительскую сцену прозрачностью при рисовании встроенного popup. Нативное прозрачное окно и QGraphicsProxyWidget требуют разных условий очистки.
- Подсказки проверяйте как реальные окна: непустое содержимое, локализованный текст, экранированные данные, читаемый текст и рамка в тёмной/светлой теме. Переключатель подсказок должен применяться и к дочерним всплывающим спискам.
- Для общих визуальных изменений проверяйте поддерживаемые языки (включая RTL и длинные подписи), обе темы, масштаб интерфейса и DPI/несколько мониторов. Используйте изолированный профиль через tools/run_regression_tests.py; не меняйте буфер и рабочие настройки пользователя.
- Регрессионный тест должен воспроизводить пользовательское действие и проверять видимый результат. Не ослабляйте проверку геометрии, чтобы скрыть обрезание; корректируйте устаревший контракт только при намеренном изменении поведения.
- Для дефектов прокрутки проверяйте доставку Paint и уже нарисованное содержимое до наведения курсора. QWidget.grab()/render() принудительно обновляют картинку и могут скрыть такой дефект; у прозрачного внешнего popup используйте непрозрачную внутреннюю область списка с согласованным фоном.
- Масштаб popup определяйте по фактическому способу отрисовки. BypassGraphicsProxyWidget не отсоединяет ранее созданный Qt proxy: встроенному списку нельзя повторно применять масштаб нативного окна. Проверяйте сохранённый proxy, позднее встраивание после Show и повторное открытие при дробном масштабе; шрифт поиска, флаги, строки и категории должны масштабироваться один раз. Сохранение позиции поиска не должно выводить список за изменившиеся границы экрана.
- Общие вкладки и кнопки сервисного окна должны сохранять координаты при переключении содержимого и изменении пояснений. Проверяйте положение через mapTo(диалог), включая дробные масштабы (например81/103/137%), а не только локальную geometry() вложенного контейнера.
- При отчёте различайте проверку реального окна, Qt offscreen и подставные ответы API. Не обещайте проверку на платформе, которую фактически не запускали.
- Флаги языков берите из общего SVG-каталога, загружайте через load_icon и рисуйте через paint_icon из src/icon_rendering.py: общий загрузчик сохраняет рамку при ограничениях QtSvg 5. Не растягивайте заранее уменьшенный QPixmap вместе с GraphicsProxy: реальный deviceTransform учитывает плотность экрана и масштаб сцены ровно один раз.
- Длительные действия настроек показывайте через src/ui_operations.py: файловую работу выполняйте в фоне, GUI меняйте короткими этапами, индикатор останавливайте на успехе, ошибке и закрытии. Не добавляйте задержку ради анимации, вымышленные проценты или прогрев OCR для такого действия.
- У непрозрачных сервисных окон очищайте фон после перемещения дочерних элементов. Сохраняйте внутренний отступ для наружной рамки: непрозрачный дочерний контейнер не должен закрашивать её по краям. Проверяйте и обычное состояние, и длинный статус фоновой операции.
- Действия обслуживания движка держите в меню выбранного движка; кнопки у таблицы относятся к языковым пакетам. Вспомогательные действия меню создавайте как QAction с владельцем, чтобы скрываемая кнопка не появлялась отдельным окном при компоновке.
- При добавлении элементов настроек обновляйте `src/settings_retranslate.py`: смена языка должна переименовывать существующие элементы, сохраняя вкладку, значения и подключения сигналов. Проверяйте соответствие текстов/подсказок новой и уже открытой формы через `tests/test_engine_center_workflow.py`. Проверка установки движка не должна импортировать его модель в GUI-поток.

## Структура репозитория

- В корне оставляйте не более пяти файлов: README.md, LICENSE, AGENTS.md, .gitignore и .gitattributes. Код и точка входа находятся в src/, зависимости — в tools/requirements/, CMD-ярлыки — в tools/shortcuts/, остальные документы — в docs/.
- После переносов проверяйте сборочные спецификации, GitHub Actions, запуск python src/main.py и изолированные тесты. Пользовательские данные и ключи не переносите в Git.
