неполном пакете и восстановление старых файлов после ошибки/блокировки.

## Что исправлено

1. **OCR не должен падать из-за журнала.** Раньше импорт `ocr` пытался открыть
   лог рядом с исходниками; в Linux при подключении исходников только для чтения
   это останавливало загрузку модуля. Теперь исходная и упакованная версии берут
   журнал из общей папки данных. Ошибка создания папки/файла журнала не блокирует
   OCR. Добавлены пять проверок путей, отказа записи и повторного открытия.
2. **Lingva возвращала оригинал вместо перевода.** `lingva.ml` на двух разных
   английских предложениях ответила HTTP 200 с неизменённым исходником для `en → ru`.
   Этот сервер удалён из списка. Остальные серверы Lingva при проверке отвечали
   HTTP 500, поэтому сейчас показывается ошибка выбранного провайдера.
   Автоматической подмены переводчика нет.
3. **Функциональная проверка ошибочно считала эхо успешным переводом.** Проверка
   фиксированного английского тестового предложения теперь требует русского текста
   в ответе. Правило применяется только к QA-примеру: имена, адреса и числа
   пользователя по-прежнему могут законно остаться неизменными. Четыре новых
   теста проверяют саму проверку. Недоступная среда Argos также больше не считается
   успешной проверкой готовности.

Контракт REST/GraphQL и дополнительные серверы сверены с
[официальным репозиторием Lingva](https://github.com/thedaviddelta/lingva-translate#public-apis).
Вывод о недоступности сделан по реальным запросам в этой сессии, а не по списку
серверов в документации.

## Реальные движки и внешние сервисы

- Google, MyMemory и LibreTranslate (`translate.disroot.org`) перевели
  синтетическое английское предложение на русский. Пользовательский текст не
  отправлялся. Это проверка доступности на момент запуска, не гарантия работы
  внешнего сервиса в будущем.
- Lingva сейчас не прошла живую проверку; запросы к дополнительным серверам
  из документации дали HTTP 403/404/500 либо ошибку соединения.
- Windows OCR распознал английский тестовый текст точно, в том числе с AUTO.
- Tesseract реально распознал текст в Linux X11-проверке. Windows Tesseract,
  EasyOCR, локальные модели RapidOCR и Hy-MT в изолированном тестовом каталоге
  не установлены: их реальное распознавание/перевод здесь не подтверждены.
  Протоколы worker, скачивание/удаление и ошибки проверены автоматическими тестами.
- Среда Argos загружается; качество перевода скачанной языковой моделью в этой
  проверке отдельно не проверялось. Пакеты пользователя не изменялись.

## Что остаётся проверить на целевых устройствах

- **macOS arm64 и Intel:** переносимые тесты Mac-ветки прошли на Windows/Linux,
  но это не запуск Cocoa, Carbon, Apple Vision или ScreenCaptureKit. Нужен Mac
  для разрешений записи экрана/Accessibility, меню, сворачивания, завершения,
  хоткеев, Retina и помощника поверх других окон. Нативная сборка ожидает команды
  пользователя. Текущий workflow macOS включает сборку; он не запускался.
- **Windows — живой рабочий стол:** Qt в текущем агентском сеансе видит экран
  1152×864, но захват тестового зелёного окна даёт чёрные пиксели. Поэтому проверка
  динамического вывода остановилась на распознавании исходного окна. Рендер самого
  QWidget и OCR синтетических изображений работают. Исключение окон из живого
  Windows-захвата и взаимодействие с другим приложением нужно перепроверить в
  обычной пользовательской сессии.
- **Linux Wayland:** логика и ошибки портала покрыты тестами; нативная проверка
  этой сессии использовала X11/Xvfb. Реальный портал Wayland и разные композиторы
  не проверены. Xvfb также не заменяет проверку на физическом мониторе.
- **Готовые пакеты:** запуск собранного приложения, подпись, установка конечных
  Windows/MSIX/AppImage/macOS пакетов остаются отдельным этапом после разрешения
  на сборку. Проверка исходников не подтверждает содержимое будущего бинарного файла.
