# Проверка macOS — 19 сентября 2026

Проверены исходники ветки `codex/windows-mac-sync` поверх `d3144cf`, общие
регрессии и настоящие бинарные зависимости для Apple Silicon и Intel.
Среда проверки: Windows / Python 3.12.10 и Ubuntu 24.04 / Python 3.12 в контейнере.
Нативного Mac в этой сессии не было. Приложение, DMG и ZIP не собирались,
сертификаты не менялись, релиз не публиковался.

## Исправленные ошибки

1. **Автозапуск.** Сохранённая настройка могла снова включать LaunchAgent с
   `Disabled=true` или `RunAtLoad=false`, заменять повреждённый/чужой plist,
   терять дополнительные параметры при восстановлении пути. Ошибка записи
   могла прервать запуск приложения; повреждённый XML не всегда обрабатывался.
   Автоматическое восстановление теперь обновляет путь только действующего
   агента приложения, сохраняет дополнительные параметры и прежний файл при
   ошибке. Отключённые и невалидные записи не перезаписываются. Это проверка
   содержимого plist, а не базы отключений `launchctl` или интерфейса Login Items.
2. **Переустановка Tesseract.** Новый runtime становился активным без скачанных
   ранее языковых моделей. Перед публикацией нового manifest теперь переносятся
   отсутствующие модели, включая вложенные каталоги. Новые комплектные модели
   не заменяются старыми. Ошибка копирования, записи manifest или отмена оставляет
   прежнюю установку активной. Системные/Homebrew-модели не затрагиваются.
3. **Отмена установщика.** Завершение дочернего процесса между проверкой его
   состояния и отправкой SIGTERM/SIGKILL могло заменить исходную причину отмены
   на `ProcessLookupError`. Эта гонка обрабатывается с последующим ожиданием
   завершения процесса. Код также используется подготовкой приватного Python.
4. **Отмена захвата.** Уже отменённый запрос больше не начинает асинхронный
   захват экрана через нативный API.

Добавлены 28 регрессионных случаев в `test_macos_deep.py` и
`test_macos_capture.py`. До исправлений воспроизведены сбои автозапуска,
потеря доступности языков при переустановке, обе гонки остановки процесса и
ненужный старт отменённого захвата. Дополнительно проверены ошибки SHA-256,
пустые ответы/ошибки захвата, опоздавшие callback после timeout, исключение
собственных окон, отрицательные координаты второго монитора и плотности 1/1.5/2.
Для Cocoa/Quartz/ScreenCaptureKit здесь используются имитации границ API.

Ошибок нет. Оба полных прогона подтвердили `USER_DATA_UNCHANGED: True`;
использованы отдельные каталоги настроек и Qt offscreen. Пропуски платформенных
проверок не считаются успешными тестами нативного Mac. В контейнере также нет
части опциональных зависимостей Linux desktop. Все 170 Python/spec-файлов
прошли синтаксический разбор; скрипты setup/build macOS — `bash -n`.

Существующий macOS workflow теперь включает все восемь файлов
`test_macos_*.py`, а не только `test_macos_support.py`, использует изолированный
запуск и сохраняет XML/JSON с результатами отдельно от сборки. Workflow в этой
сессии не запускался; его нативный результат ещё предстоит получить.

## Настоящие зависимости и архивы

Для CPython 3.12 и цели `macosx_13_0` скачаны wheels из
`requirements-macos.txt`, PyInstaller и pytest: по 54 архива для arm64 и x86_64.
Проверены Mach-O заголовки внутри архивов: 390 файлов arm64 и 358 x86_64,
всего **748**. У каждого есть нужная архитектура и указанная минимальная
версия macOS не выше **13.4**; ошибок разбора нет. Universal-файлы проверялись
по срезу нужной архитектуры.

Это проверка реально скачанных файлов, а не только wheel-тегов. Она не заменяет
нативную установку: environment markers pip оценивались в Linux; платформенные
дополнительные зависимости, dyld, системные frameworks и подпись требуют Mac.
Argos, устанавливаемый отдельной командой без зависимостей, и опциональный стек
EasyOCR/PyTorch не входят в этот подсчёт 748 файлов.

Скачаны четыре закреплённых установочных файла; SHA-256 каждого совпал с кодом:

Дополнительно проверены 33 arm64 и 32 Intel Mach-O-файла этих архивов:
архитектуры совпадают, минимальная macOS не выше заявленных для Hy-MT **14.0**.
Mac-бинарники здесь не запускались. Модель Hy-MT и языковые пакеты из сети
повторно не скачивались; настоящая установка движков на Mac не выполнялась.

Локальные свидетельства сохранены в игнорируемом `.tmp`: логи
`mac-audit-full-windows.log`, `mac-audit-full-posix.log`, результаты

Эти тяжёлые и временные артефакты в Git не включены.

## Следующая проверка на настоящем Mac

Использовать актуальную ветку `codex/windows-mac-sync`. Исторический нативный
отчёт [MACOS_QA.md](MACOS_QA.md) относится к предыдущей проверке, а не доказывает
работу сегодняшних изменений. После настройки окружения:

```bash
bash tools/setup_macos_env.sh
.venv-macos/bin/python tools/run_regression_tests.py --output .tmp/mac-native-regression
QT_QPA_PLATFORM=cocoa .venv-macos/bin/python -m pytest -q tests/test_macos_*.py
QT_QPA_PLATFORM=cocoa CLICKNTRANSLATE_EXTENDED_SMOKE=1 \
  .venv-macos/bin/python main.py --smoke-test .tmp/mac-native-smoke/report.json
```

Первый прогон намеренно offscreen. Второй и третий требуют интерактивной
графической сессии Mac. Нужны ручные проверки:

- Выдача, отказ и отзыв Screen Recording/Accessibility; горячие клавиши в
  другом приложении, конфликт сочетаний, Cmd+C/Cmd+V без потери фокуса.
- Захват всего экрана/области и динамический перевод на macOS 13.4 и 14+,
  Retina и обычный монитор, второй монитор слева/сверху; оверлей не должен
  попадать в собственный OCR.
- Cocoa popup, светлая/тёмная темы, масштабирование, трей, shadow mode и Dock;
  выход из приложения и повторный запуск без зависшего процесса.
- Login Items после перемещения `.app`, перезахода в сессию и системного
  отключения фонового элемента; отдельно состояние `launchctl`.
- Настоящие установка, отмена, переустановка и удаление Tesseract/EasyOCR/Hy-MT,
  сохранение языков, Vision и выбранный пользователем переводчик без подмены.
- Нативный Intel и нижняя граница macOS 13.4. Заголовки бинарников сами по себе
  не доказывают работу на этих системах.

Сборку и публикацию выполнять только после отдельной команды пользователя.
