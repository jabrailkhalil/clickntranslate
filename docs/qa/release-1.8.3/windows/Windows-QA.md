## Качество PP-OCRv5

На пяти русских однострочных PNG исходник 1.8.3 и локальная тестовая Windows-сборка 1.8.2 от 14 ноября выдали одинаковый текст. Одна строка была точной из пяти. После подачи прямоугольника всей строки с полем 8 пикселей прямо на распознаватель все пять были точными. Для одного изображения ориентационный классификатор потерял слово «Сохранить». На другом детектор выделил первую область около x=66 при начале исходного текста x=18. Эти потери уже присутствовали в ответе RapidOCR до упорядочивания блоков приложением. [Сравнение версий](rapidocr-comparison-report.json), [разбор стадий](rapidocr-stages-report.json).

В дополнительном опыте с двенадцатью изображениями на русском и английском штатное значение 736 дало 8 точных строк. При 384 было 9, при 512 — 11, при 448 — 12. Вывод относится к этому набору. [Строки для всех семи значений](rapidocr-detector-limits.json).

После исправления приложение снижает масштаб детектора только для невысоких широких фрагментов на английском или кириллице. Для тех же двенадцати изображений оба независимых вызова дали 12 точных строк. Первый вызов проверил движок непосредственно, второй запустил штатный процесс `python src/ocr_worker.py` и проверил его JSON-ответы. Исполнились все 19 автотестов этого модуля. [Исходные строки и ответы worker](rapidocr-release-windows.json), [19 тестов](final/rapidocr/results.xml).

## Выделение и защита от замены

На отдельной неинтерактивной станции с невидимыми Win32-окнами поток владел фокусом на каждом из четырёх контролов. Windows оставила глобальный foreground равным нулю. Поэтому для чтения через штатный обработчик UIA тест передал известный HWND вместо глобального поиска сфокусированного объекта. В остальном вызовы TextPattern, чтение диапазонов и проверка тождества элементов выполнила сама Windows. При запросе замены со штатным глобальным поиском приложение вернуло `focus_changed`. При подстановке foreground и фактических UIA RuntimeId разных контролов в одном окне оно вернуло `editor_changed`. Обе ветви завершились до записи в буфер и отправки сочетаний клавиш. [Нативный протокол](native-selection-report.json).

## Условия запуска

Применялись CPython 3.12.10, PyQt5 5.15.11, Qt offscreen и отдельная неинтерактивная оконная станция Windows для каждого дерева процессов. Автотесты использовали буфер в памяти, а нативный тест — отдельный системный буфер неинтерактивной оконной станции. Тесты mutex использовали собственные скрытые HWND. Работавшая у пользователя копия 1.8.2 продолжала работать. Стенд подтверждал версию установленного приложения через его публичный launcher в режиме редактора макета с `--update-ack`. Живое выделение в стороннем редакторе, физические несколько мониторов, пользовательские глобальные хоткеи и регистрация MSIX в Windows остались за пределами местного прогона. Производственной подписи у локальных пакетов нет.
