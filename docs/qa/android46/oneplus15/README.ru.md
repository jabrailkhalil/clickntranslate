# Android 1.8.3 на OnePlus 15

25 ноября 2026 года на физическом OnePlus 15 с Android API 37 проверили ARM64-сборку 1.8.3 (code46) в отдельном тестовом профиле. В базовом прогоне прошли 113 из 124 тестов. Вместе с отдельными прогонами на устройстве прошли 128 разных тестов. Для двух сценариев в тестовом профиле отсутствовали нужные компоненты — Shizuku и русский офлайн-голос. Системное обновление APK проверили отдельно. На ПК прошли все 1 929 JVM-тестов. Android Lint завершился с 975 предупреждениями и 42 информационными сообщениями, ошибок не зарегистрировано. [Машинный протокол](results.json)

GitHub Actions проверил те же исходники на Android 15. В базовом запуске прошли 117 тестов, 14 сценариев требуют отдельных условий. Дополнительно успешно прошли четыре группы проверок системного захвата и арабского OCR. [Прогон Android 15](https://github.com/jabrailkhalil/clickntranslate/actions/runs/45675737884)

## Обновление с 1.8.2

Для проверки собрали исходники 1.8.2 (code7) и 1.8.3 (code46) с одним тестовым сертификатом и идентификатором `dev.clickn.translate.upgradeqa`. В старой версии сохранили результат английского перевода на русский и цветовую тему Ocean. В обоих случаях APK открыл системный установщик Android.

| Действие | Что произошло |
| --- | --- |
| Нажали «Отмена» | Установщик вернул `RESULT_CANCELED`. Остались code7, запись истории и выбранная тема. |
| Повторили установку и нажали «Обновить» | Установщик вернул `RESULT_OK` и `INSTALL_SUCCEEDED`. Приложение стало code46. Репозиторий истории прочитал из Room прежние дату, исходный текст, перевод, оба языка и название сервиса. Тема и время первоначальной установки сохранились. |

Для проверки обновления поверх публичной 1.8.2 нужен APK code46 с производственной подписью. Обновление с тестовой code45 остаётся отдельным сценарием. [Историческая проверка подписанной 1.8.2 → code44 на эмуляторе](../../archive-restoration/gallery44/original-upgrade/result.json)

## Захват экрана и действия с выделенным текстом

В системном диалоге сначала отклонили запрос MediaProjection, затем повторили запуск и разрешили захват тестовой карточки. При её закрытии Android отозвал проекцию, пока переводчик ещё ждал ответ по HTTP. Поздний ответ не вернул прежнюю плашку. После нового согласия приложение показало «Зелёная дверь» за 1,583 с. В режиме захвата всего дисплея Android передал кадр 1272 × 2772 за 37 мс. Из области 1166 × 556 приложение распознало фразу целиком и показало результат за 1,144 с. На каждый перевод отвечал локальный тестовый сервер. После остановки системное разрешение освободилось. [Сценарий системного захвата](../../../../app/src/androidTest/java/dev/clickn/translate/capture/PhysicalProjectionConsentIntegrationTest.kt)

Прошли четыре проверки видимого интерфейса. При замене выделения через системное действие `ACTION_PROCESS_TEXT` приложение вернуло вызывающей стороне проверенный перевод. При отмене оно вернуло `RESULT_CANCELED` без текста для подстановки. Ещё две проверки подтвердили обнаружение разрешённого доступа к статистике использования и открытие системной плавающей панели действий в окне наложения. Для запуска этих тестов на API 37 обновили тестовую библиотеку Espresso до 3.7.0. [Исправление в AndroidX Test](https://developer.android.com/jetpack/androidx/releases/test#espresso-3.7.0)

## Память и импорт локальных моделей

Перед загрузкой Sakura память процесса по PSS составляла 203 006 КиБ, перед выгрузкой — 2 602 312 КиБ. В первом замере после выгрузки, через 116 мс, отображений файла GGUF в процессе уже не было. Через 352 мс PSS снизилась до 214 441 КиБ, через 2,121 с составила 212 574 КиБ. Это измерение одного цикла на данном устройстве. [Тест Sakura](../../../../app/src/androidTest/java/dev/clickn/translate/llm/SakuraLocalTranslationIntegrationTest.kt)

На ПК воспроизвели два сбоя при работе с локальными моделями.

- Если убрать последние 8 МиБ из исправного Hy-MT2, прежняя проверка принимала файл, а движок не мог загрузить один из тензоров. После исправления проверяются размер штатной модели и границы данных тензоров GGUF. Испорченная копия отклонена, прежняя рабочая модель сохранилась, временных файлов после отказа не осталось. На OnePlus через системный интерфейс файлов приложение отклонило обрезанные данные и под штатным, и под пользовательским именем. При повторной загрузке неполной старой модели приложение обратилось к серверу. Получив HTTP 503, оно сохранило прежний файл. Полную переименованную модель установило и затем повторно использовало без сетевого запроса.
- Если нативный вызов `prepare` получал отказ при создании контекста, загруженная модель оставалась в памяти. На ПК воспроизвели такой отказ. Исправленная функция освобождает модель ровно один раз. После повторного отказа следующая инициализация прошла успешно. Измерения памяти Sakura выше относятся к обычной выгрузке модели на телефоне.

## Ограничения устройства

Shizuku 13.6.0 при запуске ищет свой менеджер у владельца устройства (`user 0`). В этом профиле на OnePlus менеджер отсутствовал. Штатную авторизацию и получение кадров через Shizuku на этом телефоне подтвердить не удалось. Прежний успешный прогон с захватом двух абзацев относится к эмулятору API 36 и code42. [Условие запуска сервера Shizuku](https://github.com/RikkaApps/Shizuku/blob/v13.6.0/server/src/main/java/rikka/shizuku/server/ShizukuService.java#L73-L116) · [Результат на эмуляторе](../../archive-restoration/ocr42/shizuku.json)

Проверка обновления с производственной подписью, прослушивание через динамик и испытания на физическом устройстве с Android 8 или страницами памяти 16 КиБ остаются открытыми. После проверки экран вернули владельцу, а временный профиль с APK и весами моделей удалили.
