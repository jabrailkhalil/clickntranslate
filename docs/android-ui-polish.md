# Доработка Android UI

Проверено 3 октября 2026 года в локальной ветке `codex/android-ui-polish`, основанной на `origin/android` (`237866ef54eae9051c0f78d0807eb3dc6b2e30aa`). Изменения загружены в ветку `android`. Версия приложения сохранена: 0.3.1, versionCode 4. По отдельному запросу пользователя добавлен [Preview APK](../artifacts/android/README.md); тег и публикация GitHub Release не создавались.

## Изменения

- Главный экран стал компактнее: убраны повторяющиеся разрешения, готовность показывает необходимые действия, остальные проверки раскрываются отдельно. Карточки действий имеют одинаковую высоту, подписи языков выровнены.
- При первом запуске можно выбрать тему по миниатюре. Тот же выбор доступен в настройках. Миниатюры используют реальные палитры приложения; исправлены пары текста и фона, бумажные темы, AMOLED и границы светлых карточек.
- Новый профиль выбирает язык перевода по системной локали. Китайские сервисы и специальный профиль манги видны в основном выборе при китайском языке интерфейса или перевода; текущий сервис и профиль сохраняются. Другие сервисы можно раскрыть вручную. Китайские технические сообщения заменены, языковые примеры для китайских моделей сохранены.
- Возвращён оригинальный CT-логотип из desktop-приложения. Его PNG совпадает с исходником побайтно. Обновлены адаптивные и монохромные значки Android.
- Подключены статичные Честер, Док, Pancake, Mochi, Bubu и Momo. Честер — нарисованный лис; Док использует исходного робота. Источники и точный запрос генерации: [Android UI assets](android-ui-assets.md).
- В «Настройки → Плавающая кнопка» доступны персонаж, логотип, значок действия или своё изображение, размер и прозрачность. Это окно приложения поверх других приложений Android. Картинка меняется сразу; режимы перевода, жесты и меню работают независимо от её оформления. Значок текущего действия остаётся виден на персонаже.
- Импорт картинки плавающей кнопки хранится отдельно от картинки шапки и значка запуска, ограничен 10 MiB и сохраняет масштабированное изображение до 512 px. Ошибка импорта сохраняет предыдущую картинку.
- Исправлен контраст окон перевода, выбора языка и профиля: общая палитра, непрозрачный текст, читаемые действия на светлом и тёмном фоне.
- Проверены файлы, комментарии, имена локальных и удалённых веток и заголовки коммитов Android: упоминаний стороннего приложения, указанного в запросе, не обнаружено.

Runtime-проверки покрывают первый запуск и сохранение темы, переключение локалей, смену персонажа и восстановление выбора, живую смену картинки окна без изменения действия, импорт и обработку ошибки, оригинальный адаптивный значок. Проверки HTTP подтверждают системный целевой язык для пустого или автоматического выбора и сохранение явно выбранного языка.

Команды из корня Android worktree:

```powershell
.\gradlew.bat --no-daemon -PruntimeUiTests :app:testDebugUnitTest --console=plain --no-configuration-cache
.\gradlew.bat --no-daemon -PuiSnapshots :app:verifyPaparazziDebug --tests dev.clickn.translate.ui.MobileScreenshotTest --console=plain --no-configuration-cache
.\gradlew.bat --no-daemon :app:lintDebug -x ':llama-android:configureCMakeRelease[arm64-v8a]' -x ':llama-android:buildCMakeRelease[arm64-v8a]' --console=plain --no-configuration-cache
```

Paparazzi запускается отдельно: Layoutlib подменяет Android API, от которых зависят обычные проверки преобразования китайского письма. Полный набор обычных и Robolectric-тестов проходит без Layoutlib.

## Ограничения проверки

Физический Android-телефон не был подключён; снимки созданы Android Layoutlib, runtime-проверки выполнены Robolectric. Нативный движок не менялся. Первичный CMake на Windows остановился на генерации Vulkan headers: Ninja сообщает `manifest 'build.ninja' still dirty after 100 tries`. Причина подтверждена: пути временных файлов превышали 260 символов. Короткий каталог сборки устранил эту ошибку, после чего обнаружилось отсутствие Visual Studio, необходимой для host-генератора Vulkan shaders. Поэтому местный lint выполнен с исключением двух нативных задач. Имя `Release` у этих CMake-задач определяется существующей конфигурацией библиотеки и используется также при debug-проверке приложения.

Заключительный прогон проверки 17 снимков и lint завершился успешно. Предупреждения lint сохранены в отчёте `app/build/reports/lint-results-debug.html`; нулевое число ошибок не означает отсутствие предупреждений.
