## Performance constraints

The preview uses one shared cache of ten 32px frames and their mirror images:
69,120 bytes of RGBA pixels with the current asset (plus Qt/Python object
metadata). Original-sized decoded images are temporary. No per-frame decoding,
file access, model loading, screen polling, worker or global input hook.

The coarse timer runs at most 12.5 times/s, only on a visible, non-minimized main
page while the application is active. It also pauses on hover/keyboard focus,
so the moving target can be clicked. A hidden page has no running timer. The
visual layout editor detaching the sprite stops movement as well.

The scaled main view uses bounded dirty rectangles rather than repainting the
whole window for every sprite frame. Theme and scale changes explicitly request
a full viewport repaint to retain the previous old-theme-strip fix.

`python tools/qa_ui_polish.py --benchmark-seconds 5` creates screenshots and a
machine-readable sample under `.tmp/ui-polish-qa` with disposable app data.
It never registers hotkeys, changes autostart or sends translation requests.
Offscreen measurements are not a Windows desktop/GPU or whole-app idle guarantee.

A preliminary Linux/offscreen sample of approximately 3 seconds per state:
active 38 ticks, about 0.79% of one CPU core, largest dirty rectangle 0.216% of
viewport; inactive/minimized/hidden: zero ticks and zero viewport paints.
The short sample is a diagnostic, not a statistical performance benchmark.

## SHA manifest: intentionally retained at the portable root

`program-files.sha256` is an integrity inventory, not an unpacked dependency.
The **already installed** `ClicknTranslateUpdater.exe` is copied to a temporary
location and runs an update; it is not replaced by the helper inside the new
package before verification. Older helpers look for the inventory at the
portable root and verify it **before** launching/acknowledging the new app.

Moving that file into `app/` in this package would therefore break the update
path from existing installations and can trigger rollback. A future migration
needs a compatibility release and tests involving an actual old helper. This
branch does not rename/move the manifest, change its contents/format, weaken
integrity checks, change release checksum asset names or modify the updater.
Executables/dependencies remain under the existing `app/` arrangement.
