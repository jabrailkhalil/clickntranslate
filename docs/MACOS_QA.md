## Последнее изменение: восстановление после закрытия

Установленная копия оставалась живой после крестика, но её главный поток
застрял в `NSStatusBarButton.rightMouseDown` → `NSCell.trackMouse`.
IPC принимал `show` и `quit` в очередь, а Qt не мог выполнить их.

события отпускания мыши не установлена, его настройки не менялись.

Для собственных status buttons локальный монитор теперь поглощает нажатие
и откладывает открытие того же нативного меню Qt до возврата из обработчика.
Так NSButton не начинает второе ожидание mouse-up после закрытия NSMenu.

показывает главное окно независимо от `start_minimized`; эта настройка остаётся
действующей при автоматическом запуске. Крестик по-прежнему переводит приложение
в режим тени без Dock. Ошибки восстановления окна теперь попадают в лог.

Одна узкая проверка на настоящем Cocoa прошла: правое нажатие по собственному
status button, закрытие меню через Escape без mouse-up, возврат к Qt-таймерам,

пользователя. Разрешения macOS в этом обновлении не проверялись.

Перед заменой сохранены данные и предыдущая `.app`; настройки не редактировались.

## Предыдущий цикл: режим тени в верхней строке меню

По запросу пользователя режим тени теперь переключает `NSApplication` в
`Accessory`: главное окно и значок Dock скрыты, верхняя иконка и горячие клавиши
остаются. «Открыть» в меню возвращает `Regular`, окно и Dock. Крестик главного
окна, кнопка «Режим тени», повторное скрытие горячей клавишей и запуск с сохранённой
настройкой `start_minimized` используют один путь. Обычное сворачивание остаётся
в Dock; отсутствие трея сохраняет этот доступный способ возврата.

На macOS клик по верхней иконке только открывает нативное меню. Он больше не
переключает главное окно одновременно с меню. Меню принадлежит окну приложения,
а при смене языка прежний экземпляр освобождается. Окна перевода в тени не
возвращают главное окно или Dock. Выбранные OCR и переводчик сохраняются.

Нативная проверка также выявила смещение после восстановления из Dock: Qt
повторно применял обычное состояние к фиксированному окну после асинхронного
`deminiaturize`, что запускало лишний `zoom`. Восстановление теперь передано
AppKit; позиция, сохранённая до скрытия, восстанавливается. В тесте окно в
`(40, 75)` больше не уезжает в `(258, 113)`.

На этом Mac работает Ice. До раскрытия его скрытой области собственный
`NSStatusBarWindow` находился в `(-4630, 776)`; пользователь затем подтвердил,
что раскрыл область и увидел иконку. Настройки Ice не менялись. Координаты иконки
в отчёте показывают фактическое состояние, включая возможное скрытие Ice;
наличие status item не выдаётся за доказательство физического клика.

Регрессия режима тени проверяет 13 состояний, сохранение выбранных провайдеров
и позиции окна, живое меню из шести действий, а также 10 Carbon callbacks,
пока приложение работает без Dock. Промежуточное падение полного набора оказалось
текстовым тестом Linux: он искал `self.hide()` только в первых 400 символах метода.
После добавления Mac-логики поиск перестал охватывать метод. Тест заменён проверкой
реального поведения: без трея вызывается обычное сворачивание, `hide()` не вызывается.

## Исправление 7 сентября: окна открываются в левом верхнем углу

На Cocoa воспроизведены две причины: настройки находятся внутри масштабируемого
`QGraphicsProxyWidget`, поэтому `owner.window()` возвращал внутренний холст с
координатами `(0, 0)`; общий обработчик оформления перед первым показом вызывал
`move()`, отменяя автоматическое расположение Qt. Главное окно также сохраняло
начальную позицию `(0, 25)` вместо центра доступной области экрана.

Общий расчёт теперь находит настоящее нативное окно владельца, учитывает его
положение, окончательный размер диалога и доступную область нужного монитора.
При скрытом владельце используется экран под указателем. Главное окно при первом
показе центрируется на экране; перемещение пользователем и повторный показ сохраняют
его положение. Явно заданные координаты и привязка выпадающих списков сохраняются.
Большие окна сдвигаются внутрь доступной области, чтобы кнопки оставались доступны.

Нативный диагностический прогон до/после: главное окно `(0, 25)` → `(170, 163)`;
при 100% окно обновления `(81, 104)` → `(249, 244)`, пакеты `(0, 25)` → `(118, 25)`,
установка Argos `(0, 25)` → `(199, 132)`. Верхняя граница пакетов остаётся на 25:
его высота 698 требует ограничения доступной областью экрана. Все 24 варианта
диагностики после исправления совпали с независимо рассчитанным центром.

1. **Запуск из Finder/Dock/автозапуска.** PyInstaller выбирал `ArgosWorker` как

2. **Геометрия Cocoa.** Метрики Aqua и собственные QProxyStyle добавляли отступы,
   нарушали расположение переключателей и поведение списков. Для собственного
   интерфейса выбран Fusion; окна, ввод и Retina остаются на Cocoa. Каждый proxy
   владеет отдельным style и не удаляет стиль приложения.
3. **Светлая тема языковых пакетов.** Фон вкладок теперь задан явно и не наследует
   тёмную системную палитру; проверено на снимках до/после исправления.
4. **EasyOCR после удаления и переустановки.** Обнаружен настоящий сбой native
   Torch/NumPy при повторном импорте в одном процессе. На Mac OCR helper теперь
   используется и при запуске исходников. Установка → распознавание → удаление →
   отмена → переустановка прошли после исправления.
5. **EasyOCR в установленном приложении.** Внешнему пакету не хватало
   `PIL.ImageEnhance` внутри frozen helper. В сборку добавлены подмодули Pillow;
   установленный OcrWorker успешно распознаёт Retina-снимок внешним EasyOCR.
6. **RapidOCR.** Настройки учитывают движок внутри bundled OcrWorker; отсутствие
   RapidOCR в отдельном Python-архиве GUI больше не означает «не установлен».
7. **Argos.** Добавлена зависимость `sacremoses`. Новые модели/индексы направлены
   в Application Support, XDG overrides сохраняются. Старый каталог
   `~/.local/share/argos-translate/packages` остаётся доступным для чтения без
   перемещения или удаления моделей.
8. **Совместимость бинарников.** Setup загружает wheels для старого deployment
   target, а не предпочитаемые хостом macOS 14 wheels. Новый build-check читает
   фактические Mach-O load commands: все 222 бинарника требуют не выше 13.4.
   Минимум уточнён с 13.0 до 13.4 из-за фактических библиотек ONNX Runtime.
9. **Гайд и тесты.** Добавлен отсутствовавший шаг показа/скрытия окна (29 шагов).
   Исправлены несовместимые сочетания имитируемых платформ и ожидания Windows
   в тестах; проверки не отключались ради зелёного результата. На Mac pytest
   теперь изолирует настройки и XDG-каталоги до импорта приложения.

## Разрешения и обязательные ручные проверки

**Ручная системная приёмка заблокирована инструментом управления интерфейсом:**
все попытки подключения вернули `Sky Computer Use service startup request failed`.
Снимки Qt-окон и нативные API-тесты не заменяют физические нажатия, работу в чужом
приложении или подтверждение системных диалогов. TCC/Gatekeeper не отключались,
разрешения не выдавались обходным способом.

## Повторение основных команд

```bash
PYTHON=/path/to/native/python3.12 bash tools/setup_macos_env.sh
.venv-macos/bin/python main.py
QT_QPA_PLATFORM=cocoa .venv-macos/bin/python -m pytest -q
bash tools/build_macos_release.sh
# После копирования из DMG:
CLICKNTRANSLATE_EXTENDED_SMOKE=1 .venv-macos/bin/python tools/smoke_macos_bundle.py /Applications/ClicknTranslate.app
```

Smoke использует временные настройки и отключает интерактивные welcome/update/guide
триггеры. Ответы переводчика в сценариях сохранения черновика контролируемые;
Cocoa/Vision/Carbon и frozen helpers настоящие. Отдельный тест Google использует
сеть. Smoke не запрашивает Screen Recording/Accessibility и не синтезирует
системный ввод в другие приложения.
