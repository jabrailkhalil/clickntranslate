# Click’n’Translate 1.7.1 — нативная проверка macOS

Дата: 6 сентября 2026 года. Ветка: `codex/macos-1.7.1`, исходный коммит
`d52a5f0`. Исправления и этот отчёт находятся в одном последующем коммите ветки.

**Результат: собрана и установлена рабочая сборка для разработки arm64.**
Нативные автоматические проверки пройдены. Полная ручная приёмка не завершена;
публичным доверенным релизом эту сборку считать нельзя. Windows/WSL-результаты
из исходной передачи не использовались как доказательство работы на Mac.

## Что исправлено на Mac

1. **Запуск из Finder/Dock/автозапуска.** PyInstaller выбирал `ArgosWorker` как
   `CFBundleExecutable` и включал `LSBackgroundOnly`. Теперь явно указаны
   `ClicknTranslate` и обычный GUI-режим. Smoke проверяет Info.plist и запускает
   приложение через `/usr/bin/open`, поэтому прямой запуск бинарника больше не
   может скрыть эту ошибку упаковки.
2. **Геометрия Cocoa.** Метрики Aqua и собственные QProxyStyle добавляли отступы,
   нарушали расположение переключателей и поведение списков. Для собственного
   интерфейса выбран Fusion; окна, ввод и Retina остаются на Cocoa. Каждый proxy
   владеет отдельным style и не удаляет стиль приложения.
3. **Светлая тема языковых пакетов.** Фон вкладок теперь задан явно и не наследует
   тёмную системную палитру; проверено на снимках до/после исправления.
4. **EasyOCR после удаления и переустановки.** Обнаружен настоящий сбой native
   Torch/NumPy при повторном импорте в одном процессе. На Mac OCR helper теперь
   используется и при запуске исходников. Установка → распознавание → удаление →
   отмена → переустановка прошли после исправления.
5. **EasyOCR в установленном приложении.** Внешнему пакету не хватало
   `PIL.ImageEnhance` внутри frozen helper. В сборку добавлены подмодули Pillow;
   установленный OcrWorker успешно распознаёт Retina-снимок внешним EasyOCR.
6. **RapidOCR.** Настройки учитывают движок внутри bundled OcrWorker; отсутствие
   RapidOCR в отдельном Python-архиве GUI больше не означает «не установлен».
7. **Argos.** Добавлена зависимость `sacremoses`. Новые модели/индексы направлены
   в Application Support, XDG overrides сохраняются. Старый каталог
   `~/.local/share/argos-translate/packages` остаётся доступным для чтения без
   перемещения или удаления моделей.
8. **Совместимость бинарников.** Setup загружает wheels для старого deployment
   target, а не предпочитаемые хостом macOS 14 wheels. Новый build-check читает
   фактические Mach-O load commands: все 222 бинарника требуют не выше 13.4.
   Минимум уточнён с 13.0 до 13.4 из-за фактических библиотек ONNX Runtime.
9. **Гайд и тесты.** Добавлен отсутствовавший шаг показа/скрытия окна (29 шагов).
   Исправлены несовместимые сочетания имитируемых платформ и ожидания Windows
   в тестах; проверки не отключались ради зелёного результата. На Mac pytest
   теперь изолирует настройки и XDG-каталоги до импорта приложения.

визуально оценены на выборке снимков Retina, геометрия шести языков проверяется
тестами. Страницы пакетов в smoke отрисовываются без фонового сетевого каталога
и без установки; реальная установка проверялась отдельно.

## Разрешения и обязательные ручные проверки

**Ручная системная приёмка заблокирована инструментом управления интерфейсом:**
все попытки подключения вернули `Sky Computer Use service startup request failed`.
Снимки Qt-окон и нативные API-тесты не заменяют физические нажатия, работу в чужом
приложении или подтверждение системных диалогов. TCC/Gatekeeper не отключались,
разрешения не выдавались обходным способом.

| Область | Проверено | Осталось проверить вручную |
| --- | --- | --- |
| TCC | Read-only preflight: Python/терминальный запуск — screen/accessibility `true`; установленная копия через LaunchServices — оба `false` | Отказ, переход в System Settings, выдача обоих доступов именно приложению, нужный перезапуск, повторный OCR/замена. **Установленная копия пока не имеет этих доступов** |
| Доступ к Desktop | Smoke из LaunchServices упёрся в файловое разрешение при сохранении снимка на Desktop; вывод smoke перенесён в временный каталог | Выбор пользовательских документов через системный диалог и разрешение файлового доступа |
| Горячие клавиши | Нативная регистрация Carbon, конфликт, снятие и повторная регистрация; тесты mapping/repeat suppression | Доставка настоящих нажатий при другом активном приложении, RU/EN, удержание, смена сочетания в UI, ISO-клавиатура |

| Динамический перевод | Нативный Quartz отслеживает тестовое окно: перенос меняет rect, сворачивание/закрытие дают hidden и пустой rect; тесты маршрутизации выбранного OCR | Полный цикл перевода поверх другого приложения, несколько областей, смена фокуса, отсутствие захвата собственного перевода, мерцание |

| UI | Cocoa-матрица и визуальная выборка всех основных типов окон | Полный ручной обход каждой подсказки, модального/системного диалога, меню трея и всех шагов гайда |

Другие версии macOS, Intel/x86_64 и две архитектуры GitHub Actions в этой сессии
не проверялись. Требование 13.4 подтверждено анализом бинарников, а не запуском
на этой версии ОС.

При одном промежуточном offscreen-прогоне был SIGSEGV в уничтожении Qt widgets
во время сборки мусора. Причина не установлена; изолированный набор, полный
нативный Cocoa-прогон и повторный полный offscreen-прогон затем прошли.
Этот промежуточный сбой не скрыт, но не воспроизведён в финальных проверках.

## Повторение основных команд

```bash
PYTHON=/path/to/native/python3.12 bash tools/setup_macos_env.sh
.venv-macos/bin/python main.py
QT_QPA_PLATFORM=cocoa .venv-macos/bin/python -m pytest -q
bash tools/build_macos_release.sh
# После копирования из DMG:
CLICKNTRANSLATE_EXTENDED_SMOKE=1 .venv-macos/bin/python tools/smoke_macos_bundle.py /Applications/ClicknTranslate.app
```

Smoke временно подменяет только настройки и интерактивные welcome/update/guide
триггеры, использует настоящие Cocoa/Vision/Carbon и frozen helpers. Он не
запрашивает Screen Recording/Accessibility и не синтезирует системный ввод.
