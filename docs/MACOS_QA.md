## Round24: проценты под результатом, фокус кнопки и динамический захват

9 сентября 2026 года, Apple M1 / arm64 / macOS 14.3. Изменения поверх `b8a7f30`.

Строка «Переводится в реальном времени...» перенесена под переведённый текст
справа в главном окне. Вместо счётчика частей выводится процент завершённых
частей запроса: от 0% до 100%. Число стоит первым и остаётся видимым в узком
окне. Строка использует прежнее место внутри фиксированного текстового блока;
окно не увеличено. То же вычисление процента применяется в окне переводчика
и документах. Раскрытие текущего запроса сохраняет уже достигнутый процент.
Ошибки и отмена не выводят успешные 100%; выбранный провайдер сохраняется.

У кнопки раскрытия отключены фокус от мыши, автоматическое назначение кнопкой
по умолчанию и нативная Mac-рамка. Общая отрисовка иконок убирает нативный
фокусный контур при работе мышью, сохраняя обозначение фокуса с клавиатуры.

В динамическом режиме Mac больше не меняет прозрачность оверлея перед каждым
снимком. Новый `macos_capture.py` на macOS 14+ использует ScreenCaptureKit
с исключением приложения целиком; на 13.4 — Quartz-композицию списка окон
без окон текущего процесса. Область и полный экран захватываются в отдельном
потоке, с разрешением Retina, отменой при закрытии и ограниченным ожиданием.
Ошибка захвата отображается без перехода на снимок с собственным оверлеем
и без подмены OCR. PyObjC ScreenCaptureKit и CoreMedia закреплены на 11.1
в Mac requirements и добавлены в Mac bundle.

Общее исправление динамического полноэкранного режима: предыдущий перевод
остаётся до готовности следующего результата, а очистка требует двух пустых
OCR-кадров. Второй кадр проверяется на следующем такте, даже если изображение
не изменилось. Windows с доступным display affinity сохраняет системное
исключение; Linux и старые Windows пока используют прежнее краткое скрытие
на время захвата. Для этого пути полное устранение мерцания не заявляется.

**Тесты не запускались**: pytest, smoke, снимков экрана и ручного прогона новых
изменений нет. Существующие сценарии адаптированы к новому расположению строки
и сохранению предыдущего кадра для будущего запуска. Новый захват требует
нативной проверки на установленной программе, нескольких областях/мониторах,

## Round22: постепенный перевод и точечная проверка автозапуска

9 сентября 2026 года, Apple M1 / arm64 / macOS 14.3.

Главное окно выполняет перевод в фоновом потоке. Готовые части Google, MyMemory,
Lingva, LibreTranslate, Hy-MT и Argos передаются в интерфейс по мере завершения.
В главном окне и окне переводчика показывается счётчик частей; документы также
обновляют результат постепенно. Дополнение текста сохраняет положение чтения.
Argos использует один worker и загруженную модель на запрос; после выдачи части
ошибка не запускает повтор всей операции. Ошибка выбранного провайдера сохраняет
готовый текст и показывается пользователю. Автокопирование и история сохраняют
только успешно завершённый результат. Изменение ввода/языков в отдельном окне
отменяет прежний запрос; его поздние части игнорируются.

В автозапуске исправлено сохранение `autostart_backend`: для Mac теперь остаётся
`macos_launchagent`, для Linux — `xdg_autostart`. Прежде общий `save_config()`
перезаписывал оба значения названием Windows-механизма. При ошибке изменения
галочка показывает фактическое состояние Mac LaunchAgent и выводит причину,
вместо молчаливого снятия галочки. Некорректный plist-массив больше не вызывает
ошибку чтения состояния.

По новой просьбе проверить галочку выполнены **только проверки автозапуска**:

- `QT_QPA_PLATFORM=offscreen .venv-macos/bin/python -m pytest -q tests/test_macos_support.py -k autostart`
  — **5 passed**, 45 deselected. В том числе отказ при удалении и некорректный plist.
- Один цикл Cocoa QCheckBox → настоящий обработчик Settings → сохранение настроек
  в отдельный файл → реальный LaunchAgent в `~/Library/LaunchAgents` → чтение
  сохранённой галочки → выключение. `plutil -lint` принял plist; путь запуска
  указывает на `/Applications/ClicknTranslate.app --autostart` через `open -a`.
  Это проверка исходного обработчика с явно заданными аргументами установленной
  программы, не нажатие в установленной `.app`. Python-запуск дополнительно
  записывает WorkingDirectory. Прежнее состояние LaunchAgent, пользовательский
  config и остальные агенты сохранены. Автозапуск пользователя оставлен выключенным.

Управление UI через CUA недоступно: сервис не запустился. Повторный вход в учётную
запись не выполнялся. [Нативный отчёт](qa/macos-1.7.1-arm64/round22/autostart-qa.json),
[результат pytest](qa/macos-1.7.1-arm64/round22/autostart-tests.log).
**Тесты нового перевода и общий UI/пакетный QA отложены**, как пользователь просил

Общий обработчик теперь непосредственно измеряет и рисует текст подсказки.

от стилей родительского элемента, с нейтральными цветами текущей темы и прозрачными

события Show и окончательного расчёта геометрии. Положение остаётся рядом с
курсором и ограничивается экраном. Изменение находится в общем модуле для всех ОС.

## Предыдущее изменение: EasyOCR без Homebrew и системного Python

## Проверка 7 сентября: разрешение записи экрана включено, API отказывает

После сообщения пользователя о включённом переключателе выполнен запуск нового
процесса **той же установленной сборки**, без изменения бинарника/подписи.
`CGPreflightScreenCaptureAccess()` снова вернул `false`; Accessibility также
`false`. Значит, одного перезапуска недостаточно. В журнале обычного приложения
видны два нажатия и два отпускания перевода области — исправленный Carbon
получает пользовательские сочетания, операция останавливается на разрешении.

Поведение согласуется с записью TCC от старой ad hoc подписи.
[Apple DTS подтверждает](https://developer.apple.com/forums/thread/819406),
что такая подпись делает новую сборку новым приложением для разрешений.
В этом цикле проверки копия не пересобиралась и не переподписывалась.

Приложение штатно завершено. Команда

## Что исправлено на Mac

1. **Запуск из Finder/Dock/автозапуска.** PyInstaller выбирал `ArgosWorker` как
   `CFBundleExecutable` и включал `LSBackgroundOnly`. Теперь явно указаны
   `ClicknTranslate` и обычный GUI-режим. Smoke проверяет Info.plist и запускает
   приложение через `/usr/bin/open`, поэтому прямой запуск бинарника больше не
   может скрыть эту ошибку упаковки.
2. **Геометрия Cocoa.** Метрики Aqua и собственные QProxyStyle добавляли отступы,
   нарушали расположение переключателей и поведение списков. Для собственного
   интерфейса выбран Fusion; окна, ввод и Retina остаются на Cocoa. Каждый proxy
   владеет отдельным style и не удаляет стиль приложения.
3. **Светлая тема языковых пакетов.** Фон вкладок теперь задан явно и не наследует
   тёмную системную палитру; проверено на снимках до/после исправления.
4. **EasyOCR после удаления и переустановки.** Обнаружен настоящий сбой native
   Torch/NumPy при повторном импорте в одном процессе. На Mac OCR helper теперь
   используется и при запуске исходников. Установка → распознавание → удаление →
   отмена → переустановка прошли после исправления.
5. **EasyOCR в установленном приложении.** Внешнему пакету не хватало
   `PIL.ImageEnhance` внутри frozen helper. В сборку добавлены подмодули Pillow;
   установленный OcrWorker успешно распознаёт Retina-снимок внешним EasyOCR.
6. **RapidOCR.** Настройки учитывают движок внутри bundled OcrWorker; отсутствие
   RapidOCR в отдельном Python-архиве GUI больше не означает «не установлен».
7. **Argos.** Добавлена зависимость `sacremoses`. Новые модели/индексы направлены
   в Application Support, XDG overrides сохраняются. Старый каталог
   `~/.local/share/argos-translate/packages` остаётся доступным для чтения без
   перемещения или удаления моделей.
8. **Совместимость бинарников.** Setup загружает wheels для старого deployment
   target, а не предпочитаемые хостом macOS 14 wheels. Новый build-check читает
