# Продолжение работы на другом устройстве

Состояние на 12 сентября 2026 года. Ветка: `codex/windows-mac-sync`.
Репозиторий: https://github.com/jabrailkhalil/clickntranslate.
Версия исходников остаётся 1.7.1. Это сохранение работы; новые установщики,
теги и GitHub Release в рамках этой задачи не выпускались.

## Получить всё

Если рабочее дерево на другом устройстве чистое:

```bash
git fetch origin
git switch codex/windows-mac-sync
git pull --ff-only origin codex/windows-mac-sync
```

Если ветка ещё не создана локально, `git switch` обычно создаст её из одноимённой
удалённой ветки. Явная команда: `git switch --track origin/codex/windows-mac-sync`.
При локальных изменениях сначала сохраните их отдельным коммитом. При расхождении
веток объедините изменения по смыслу; не используйте `reset --hard`.

Для нового клона:

```bash
git clone --branch codex/windows-mac-sync https://github.com/jabrailkhalil/clickntranslate.git
cd clickntranslate
```

Ветка включает предыдущие Windows-коммиты `fe9739f` и `192e81e`, исходный общий
Mac-код `97d3e74` и все последующие правки текущего рабочего дерева. На момент
проверки `origin/main` и `origin/codex/macos-1.7.1` указывали на `97d3e74`.
Само наличие Mac-коммита среди предков не означает совпадения поведения:
Windows-коммит повторно добавлял полноэкранный динамический запуск. Это исправлено.

## Последнее согласованное поведение

Пользователь попросил убрать лишнюю надпись, выбирать область OCR и место вывода
перевода отдельно. Подтверждённые микронастройки: размер, прозрачность,
закрепление и шаблоны.

- Динамическая горячая клавиша (в проверенной Windows-конфигурации `Ctrl+Alt+L`)
  открывает выбор: источник → место вывода → «Запустить»/Enter. До 16 пар.
- Вывод содержит только перевод. Оригинал, заголовок, языковая пара и надписи
  ожидания скрыты. Ошибки доступны через кнопку настроек.
- Кнопка «...» открывает размер текста 10–48 px, прозрачность фона 0–100%,
  закрепление, перемещение/размер через перетаскивание «↔»/«↘», сохранение
  шаблона и остановку всех пар. При перемещении вывода источник остаётся на месте.
- Шаблон сохраняет все пары сеанса, языки и настройки каждого вывода.
  Загрузка и удаление доступны при следующем выборе областей.
- Обычный динамический интерфейс работает с областями. Внутренний старый
  `GameFullscreenOverlay` сохранён для совместимости и QA. Статический перевод
  экрана остаётся отдельным действием.

Подробное поведение и история QA: [LIVE_TRANSLATION.md](LIVE_TRANSLATION.md).

## Карта изменений

| Файлы | Назначение |
| --- | --- |
| `dynamic_workspace.py` | `PairedRegionSelector`, `PairedTranslationOverlay`, `OutputControls`; независимые источник и вывод, микронастройки |
| `dynamic_templates.py` | Локализация шести языков, проверка и атомарное хранение шаблонов, координаты относительно монитора |
| `windows_overlay.py` | Нативная форма Windows-окон, проверенное исключение окон из захвата без смены прозрачности на каждом кадре |
| `game_mode.py` | Интеграция нового выбора и пар, сохранение очереди OCR/перевода, Windows-захват |
| `settings_window.py`, `main.py`, `guide_setup.py` | Новый сценарий в подсказках и обучении; устаревший выбор показа оригинала скрыт |
| `tests/test_dynamic_workspace.py`, `tests/test_game_mode.py`, `tests/test_guide_setup.py` | Регрессии пар, захвата, шаблонов и обновлённого обучения |
| `tools/qa_windows_dynamic_capture.py`, `tools/qa_windows_output_layout.py` | Воспроизводимые нативные проверки на собственных тестовых изображениях |

На этой Windows 10 build 19045 Qt-окна с `WA_TranslucentBackground` отвергали
`SetWindowDisplayAffinity(0x11)` с WinError 8. Прежний запасной путь менял opacity
перед каждым захватом, вызывая мерцание. Теперь Windows использует обычную
нативную поверхность с формой `QRegion` и проверенным `WDA_EXCLUDEFROMCAPTURE`.
Пустая маска Qt раскрывает всё окно, поэтому для полностью скрытого содержимого
нужна непустая маска за пределами окна. Не возвращать прежний opacity-fallback
на Windows. Mac сохраняет платформенный механизм исключения окон; Linux имеет
отдельный путь временного скрытия. Новый интерфейс нужно нативно проверить на Mac.

`PairedTranslationOverlay.region` всегда обозначает источник OCR;
`output_rect` — отдельное место вывода. На Windows под полупрозрачным фоном
рисуется снимок места вывода, а не исходного текста. Геометрию вывода нельзя
подменять геометрией источника. Длинный текст не должен раздвигать выбранное окно.

Шаблоны записываются через `QSaveFile` в `data/dynamic_templates.json`; повреждённый
файл не перезаписывается. Пользовательские настройки, история и шаблоны локальны.
К моменту завершения разработки пользовательских шаблонов ещё не было; тесты
использовали отдельные временные хранилища. `data/config.json` не изменён.

## Что проверено и что осталось

- Финальная проверка нового режима, обучения, главного окна и подсказок:
  **96 passed, 696 subtests**, 33.89 с. Отдельно восемь новых регрессий пар/шаблонов.
- Нативный захват source/output прошёл на 100% и 150%: по три кадра,
  исключение собственного перевода и контролов, фон места вывода, сохранение
  и повторная загрузка шаблона. Последний прогон 100% также использовал настоящий
  Windows OCR и перетаскивание/изменение размера через `QTest`.
- Старый нативный тест области/внутреннего полного экрана прошёл при 100% и 150%.
  Переводчик в этих QA детерминированный; реальные сетевые API и игры не проверены.
- Отрисованы 24 состояния нового UI: шесть языков и две темы. Найденное отсутствие
  `show()` у новых контролов шаблонов исправлено и защищено регрессией.
- Полный промежуточный прогон: **1195 passed, 46 skipped, 27 failed, 10 errors**.
  26 failures относились к удалённому шагу обучения и исправлены последующим
  профильным прогоном. Обучение теперь содержит 28 шагов и 13 рекомендаций.
  Оставшиеся 1 failure и 10 errors — известная Windows ExecutionPolicy в
  `test_windows_release_signing.py`. Полный набор после исправлений обучения
  повторно не запускался: считать весь suite зелёным нельзя.
- В Qt-тестах есть известные предупреждения фонового `autostart-probe` об уже
  удалённом `_HotkeyDispatcher`. В журнале запущенного приложения ошибок не было.
- На Mac/Linux новый сценарий ещё не проверен нативно. На другом устройстве
  проверить разрешения захвата, разные мониторы/масштабы, перекрытие источника
  и вывода, прокрутку, шаблоны после смены монитора и настоящий провайдер перевода.

## Запуск Python

Windows в этой задаче: Python 3.12.10, PyQt5 5.15.11, окружение `.venv`.
В существующем подготовленном окружении:

```powershell
.\.venv\Scripts\python.exe main.py --show-after-update
```

На Mac подготовка зависимостей описана в `tools/setup_macos_env.sh` и
`requirements-macos.txt`; используйте платформенные зависимости. После подготовки
окружения запустите его Python с `main.py --show-after-update`. Этот флаг только
показывает окно при старте, обходя сохранённый запуск в трей.

При передаче Python-версия на Windows оставлена открытой для тестов. Виртуальные
окружения, модели OCR/перевода, сборки, кэши и личные данные через Git не переносятся.
