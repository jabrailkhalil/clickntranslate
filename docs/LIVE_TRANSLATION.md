# Динамический перевод всего экрана

11 сентября 2026. Изменения исходников поверх полного переноса Mac-ветки
`97d3e74`. Новая сборка и публикация ожидают команды владельца проекта.

В настройках динамического перевода кнопка «Выбрать области или весь экран»
открывает общий выбор языков. Можно выделить области и нажать «Запустить» либо
выбрать «Автоперевод всего экрана». Используется монитор, на котором открыт
выбор. Старые настройки не запускают захват всего экрана автоматически.

Перевод появляется на месте исходных строк. Компактную панель языков, паузы и
остановки можно перетащить. Она не принимает клавиатурный фокус; остальной
оверлей пропускает мышь в приложение. Повторное нажатие настроенной горячей
клавиши динамического режима также останавливает сеанс.

## Обработка кадров

- Координаты берутся из последнего OCR-кадра, отдельно от сетевого ответа.
  Прокрутка перемещает уже переведённые строки без нового запроса.
- Кэш принадлежит одному сеансу с выбранным движком и языковой парой. Повторы
  переводятся один раз; переключения на другой провайдер при ошибке нет.
  В памяти хранится не более 512 записей и 524 288 символов.
- Новый текст подтверждается повторным распознаванием с интервалом около
  180 мс. Ожидание стабилизации ограничено, чтобы непрерывно печатающийся текст
  тоже мог переводиться. Незначительное дрожание координат сглаживается;
  изменённые числа и отрицания не объединяются по нечёткому сходству.
- Неизменившиеся кадры пропускаются; небольшое изменение отдельной надписи
  учитывается отдельно от средней разницы всего экрана. Периодическое повторное
  чтение позволяет восстановиться после ошибки OCR или провайдера.
- Старый ответ может пополнить кэш, но не вернуть исчезнувшую строку на экран.
  Два пустых OCR-кадра убирают оставшийся перевод. Пауза и потеря активности
  связанного приложения очищают текущий слой.
- Под исходными буквами рисуется непрозрачная локальная маска, чтобы оригинал
  не просвечивал через перевод. Настройка прозрачности применяется к фону
  перевода; опция показа оригинала выводит обе фразы в одной строке.

Сценарий вдохновлён описанием Fluid Translation у
[Glint Translator](https://www.glinttranslator.com/); реализация использует
собственные существующие движки OCR, переводчики и отрисовку Click'n'Translate.
Заявления Glint о задержке и совместимости не относятся к этой реализации.

## Проверка

После изменений полный набор тестов прошёл на Windows: **1202 passed,
42 skipped, 907 subtests**; на Linux (WSL Ubuntu 22.04): **1168 passed,
76 skipped, 913 subtests**. Сборка Windows была остановлена по команде владельца
до завершения; новый динамический режим проверен из исходников.

`python tools/qa_windows_live_translation.py` создаёт собственные изображения,
распознаёт их настоящим Windows OCR при плотности захвата 150% и пропускает через
живой оверлей. Ответы переводчика детерминированы; рабочий стол, реальные API и
пользовательские настройки не используются. Отчёт и изображения находятся в
`.tmp/windows-live-qa`.

Проверенные три сцены: первый кадр — один запрос, прокрутка тех же фраз — ноль,
замена одной фразы — один; исчезнувшие строки удаляются. Просмотрены отрисованные
позиции, выбор режима и панель управления в обеих темах. Регрессионные тесты
покрывают поздние ответы, выбранный провайдер, дубли, паузу/остановку, исключение
всех окон оверлея из захвата и размещение элементов на экране шириной 640 px.

На Windows используется исключение оверлея из захвата, при его недоступности
слой и панель временно скрываются на время снимка. На Mac сохранён захват с
исключением окон приложения; его нативную проверку нужно повторить на Mac.
Для Linux сохранено ограничение на Wayland: непрерывный захват через портал
не запускается. Реальные игры, эксклюзивный полноэкранный режим и задержки
сетевых провайдеров этим тестовым сценарием не проверяются.
