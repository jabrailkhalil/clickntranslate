# Углублённая проверка Linux, 19 сентября 2026

Проверка исходников после `26dee05`, ветка `codex/windows-mac-sync`.
Среда: Ubuntu 24.04.4 в отдельном Docker-контейнере, Python 3.12.3,
настоящие X11/Xvfb и headless Sway/Wayland. Исходники подключены только для чтения;
результаты и тестовые данные вынесены в отдельную папку. Дополнительно выполнена
регрессия на Windows/Python 3.12.10. Пакеты приложения не собирались.

## Воспроизведённые и исправленные ошибки

1. **Обрезка снимка другого монитора.** Расположенные слева или сверху экраны
   имели отрицательные координаты, а обрезка считала началом рабочего стола
   `(0, 0)`. Теперь используется объединение геометрий всех экранов со смещением
   относительно его начала. Проверены четыре расположения при плотностях 1×/2×.
2. **Неверная область OCR при HiDPI в Wayland.** PNG портала не содержит Qt DPR.
   Снимок выглядел правильно, но выделение на замороженном фоне брало другой
   участок. Метаданные DPR теперь выводятся из размеров снимка и логического
   рабочего стола. Проверены одноэкранное выделение цветного участка и реальные
   мониторы с масштабами 200%/100%. Sway выдаёт общий снимок в максимальном
   масштабе, поэтому DPR отдельного монитора недостаточно.
3. **Лишнее ожидание быстрого ответа портала.** Если ответ приходил внутри
   вызова Screenshot, код всё равно входил в цикл ожидания. Теперь завершённый
   запрос не ждёт тайм-аута. При настоящем тайм-ауте отправляется Request.Close.
4. **Снимок после отмены пользователем.** Ответ Cancelled больше не запускает
   резервный helper. Ошибка и отмена различаются явно. На уровне окна OCR убран
   повтор того же Wayland-запроса после пустого снимка: он снова открывал уже
   отменённый диалог разрешений.
5. **Ложная доступность портала.** Объект D-Bus мог существовать без интерфейса
   Screenshot. Доступность теперь проверяется через его свойство `version`.
   Успешный X11-захват больше не активирует портал ради записи в лог.
6. **Оставленные процессы и временные снимки.** После тайм-аута clipboard helper
   завершается и собирается через `communicate`; частичный PNG неудавшегося
   screenshot helper удаляется.
7. **Неработающие ярлыки при специальных символах в пути.** Исправлены два слоя
   экранирования `.desktop`, литеральный `%` и ограничение `=` в имени команды.
   Путь всегда передаётся аргументом; оболочка для случая `=` получает постоянную
   команду, а не строку кода из пути. GIO реально запустил 11 вариантов пути.
   Для исходного `main.py` добавлен интерпретатор: executable bit и shebang
   больше не требуются.
8. **Автозапуск после переноса AppImage.** Включённая запись теперь получает
   актуальный Exec. Настройки рабочего стола, например задержка и OnlyShowIn,
   сохраняются; идентичный файл не переписывается. Hidden и отключение через
   GNOME учитываются — старый config больше не включает их обратно. Запись
   атомарная; отказ замены сохраняет предыдущий файл.
9. **Прозрачный фон панели динамического перевода.** На Linux/macOS прозрачная
   поверхность подавляла автоматическую отрисовку фона QFrame. Панель теперь
   сама рисует фон и контур. Проверены пиксели обеих тем на обычной и прозрачной
   поверхности, затем просмотрены настоящие Linux-снимки при 200% DPI.
10. **Апостроф в пути к исходникам при сборке.** Скрипт чтения версии передаёт
    путь аргументом Python, вместо вставки в строку Python-кода. Bash-файлы
    рабочей копии приведены к LF согласно существующему `.gitattributes`.

Поведение портала сверено с документацией
[Screenshot](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Screenshot.html)
и [Request](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Request.html).
Экранирование команд соответствует
[Desktop Entry Exec](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html).

Новые сценарии сначала воспроизвели ошибки: 11 падений захвата/портала,
5 вариантов `.desktop`, зависший clipboard helper, устаревший автозапуск,
2 способа его отключения, 5 проверок HiDPI и 2 темы прозрачной панели.
Это параметризованные случаи, а не число независимых дефектов.

Полные и выборочные наборы пересекаются; их числа нельзя складывать как
уникальные тесты. Изолированные прогоны подтвердили неизменность пользовательского
каталога `data` по SHA-256. Последняя правка повторного Wayland-запроса добавлена
после старта полных прогонов и проверена отдельным набором на обеих ОС.

**Живые сервисы:** Google, MyMemory и LibreTranslate перевели EN→RU. Оба
настроенных адреса Lingva не дали успешного результата; последний вернул
`An error occurred while retrieving the translation`. Повтор в функциональной
проверке также не помог. Это оставленная видимой ошибка сервиса на момент
проверки; автоматической подмены выбранного движка нет.

Шесть пропусков функционального sweep: Argos без модели в первоначальном
изолированном каталоге, Hy-MT, обнаружение локальных RapidOCR/EasyOCR-моделей,
портал в X11-сеансе без D-Bus и упакованные workers. **Argos, RapidOCR и портал
затем проверены отдельно реально**, как указано выше. EasyOCR и Hy-MT в этой
среде не устанавливались; упакованные workers новой версии не проверялись.

`pip check` в Linux сообщает об отсутствующих upstream-зависимостях Argos
`minisbd`, `sacremoses`, `spacy`, `stanza`. Установка `argostranslate --no-deps`
задумана проектом: код подменяет разделитель предложений. Проверка настоящего
перевода Argos прошла; формально чистым результатом `pip check` это не является.

## Как повторить

Обычный полный прогон из окружения проекта:

```bash
python tools/run_regression_tests.py --output /tmp/cnt-linux-regression
```

Нативные `.desktop`-проверки используют `/usr/bin/python3` с `python3-gi`.
Для Wayland на Ubuntu тестовому контейнеру понадобились `sway`, `grim`,
`pipewire`, `dbus-x11`, `xdg-desktop-portal`, `xdg-desktop-portal-wlr`,
`xdg-desktop-portal-gtk`, `wl-clipboard`. GTK нужен для Access backend;
одного установленного WLR в данной среде было недостаточно для Screenshot.

Запускать в изолированной тестовой среде от обычного пользователя, с окружением
проекта в PATH. Скрипт запускает собственный compositor и пишет тестовую строку
в его clipboard:

```bash
dbus-run-session -- bash tools/qa_linux_wayland.sh /tmp/cnt-wayland-100
CNT_QA_WAYLAND_SCALE=2 dbus-run-session -- bash tools/qa_linux_wayland.sh /tmp/cnt-wayland-mixed
```

Скрипт создаёт собственные XDG-каталоги, сохраняет JSON/PNG/логи и завершает
свои процессы. Probe вызывает портал напрямую и запрещает helper fallback:
успешный `grim` не может замаскировать сломанный портал.

Локальные логи и изображения этой проверки находятся в
`.tmp/linux-audit/`, логи прогонов — `.tmp/linux-audit-*.log`.
Эти временные результаты не включаются в Git; новые тесты и оба Wayland QA-скрипта
включаются.

## Что остаётся непроверенным

- Свежая сборка AppImage/tar.gz, запуск frozen workers и совместимость готового
  ELF с более старой glibc. Из успешного запуска исходников на Ubuntu 24.04
  нельзя заключить совместимость бинарника со всеми дистрибутивами.
- Текущая версия на настоящих GNOME/KDE, с физическими мониторами, их
  разрешительными диалогами, системным треем и входом в сеанс. Существующая
  Hyper-V VM не предоставила доступ к рабочему столу; она возвращена в исходное
  выключенное состояние. Headless Sway не выдаётся за проверку GNOME/KDE.
- EasyOCR с настоящим torch и Hy-MT с Linux llama.cpp/моделью.
- Непрерывный перевод в Wayland остаётся отдельной нереализованной функцией.

Новые релизы, теги и сборки не создавались. Старые результаты проверки готовых
пакетов в `LINUX.md` относятся к предыдущим сборкам.
