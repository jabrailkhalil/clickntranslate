# Перенос активных исправлений старой Android-версии

Это контракт нового независимого декодера публичной SQLite-проекции. Старый код не подключается и не исполняется. JSON в unit-тестах используется только для синтетических fixtures: прежняя версия не имела подтверждённого JSON-export translation memory.

Подтверждённая исходная схема: `backup/android-remote-before-rewrite-20261024`, commit `05493e6`, `translation-memory.db`, таблица `translation_memory_entries`. Проверены только формат хранения и пользовательские семантики; старый matcher не переносился.

## API и владение данными

`LegacyCorrectionReader.read(rows: Sequence<Map<String, Any?>>): LegacyCorrectionReadResult`

Вызывающая сторона открывает SQLite только для чтения и передаёт явную публичную проекцию; helper не открывает файлы, БД, DataStore или Keystore, не получает `Context`, не читает настройки/секреты и не изменяет входные карты. Вызывающая сторона выполняет чтение вне UI-потока, отвечает за отмену между строками и закрытие Cursor/БД.

`requiredColumns` содержит ровно12 исходных столбцов:

| Старый столбец | Поле `LegacyCorrectionDraft` | Проверка |
| --- | --- | --- |
| `id` | `legacyId`, производная `identity=memory-active/v1/<id>` | Положительный целый Long; новый Room ID из него не создаётся |
| `observedSource` | `observedSource` | Первый исходный alias; непустой текст без потери регистра/абзацев |
| `correctedSource` | `correctedSource` | Второй, отредактированный alias; сохраняется независимо от первого |
| `correctedTranslation` | `translated` | Непустой исправленный перевод |
| `sourceLang` / `targetLang` | `sourceLanguage` / `targetLanguage` | Строчные language tags; явные `*`/пустая строка → `""`; `auto` разрешён только у source |
| `scopePackage` | `scopePackage` | Trim, регистр сохраняется; пустая строка — явно глобальное правило; иначе валидное имя пакета либо системный `android` |
| `appLabel` | `appLabel` | Публичное название приложения, до512 символов; название без package отклоняется как неоднозначное |
| `createdAtMs` / `updatedAtMs` / `lastUsedAtMs` | Одноимённые поля | Неотрицательные целые Long; порядок времени не предполагается из-за изменения системных часов |
| `hitCount` | `hitCount` | Неотрицательный целый Long |

Оба aliases и перевод ограничены200000 UTF-16 символов каждый. Проверяются управляющие символы и парность суррогатов; текстовые поля допускают переносы строк/табуляцию. Общий бюджет возвращаемых строк —8000000 UTF-16 символов, строк не более10000. Одна строка сверх бюджета отклоняется явно; остальные подходящие строки могут быть прочитаны в пределах лимита. `hasNext()` ленивой Sequence может подготовить одну лишнюю строку, но она не декодируется/не сохраняется. Source Cursor должен иметь собственный bounded `LIMIT` и чтение только нужных полей.

Допустимые необязательные исходные столбцы: `normalizedObservedSource`, `normalizedObservedLength`, `normalizedCorrectedSource`, `normalizedCorrectedLength`. Их значения не используются; `DERIVED_FIELDS_IGNORED` требует пересчитать новые ключи из сохранённых aliases. Неизвестный столбец отклоняет строку **до обращения к значениям**, включая случай случайно добавленного поля credentials. В issues нет исходных текстов, названий приложений, неизвестных имён полей или exception messages.

## Семантики, которые нельзя потерять

- В прежней таблице отсутствовали per-row `caseSensitive`, `enabled` и `fuzzy`. Старый runtime сопоставлял оба aliases без учёта регистра и имел общий fuzzy-путь; DTO поэтому явно предоставляет `caseSensitive=false`, `fuzzy=true`. Это описание подтверждённой политики, а не выдуманные столбцы. Если такие поля неожиданно появляются во входной проекции, строка получает `UNSUPPORTED_FIELD`.
- Включение translation memory было общей настройкой, не полем записи. Reader не делает вывод, что импорт обязан включить её. Интеграция должна сохранить выбранное пользователем состояние и не включать автоматический recall неявно.
- App-scoped исправление не должно становиться глобальным при неизвестном/пустом/повреждённом package. Отсутствующий столбец, `null`, `*`, произвольное название вместо package и label без package отклоняются; явный `scopePackage="", appLabel=""` сохраняет глобальную запись.
- Wildcard сохраняется только при явных `*`/пустой строке. Неизвестный язык не превращается в wildcard. Это метаданные новой модели: наличие wildcard-значений не означает, что прежний SQL matcher имел wildcard-сопоставление языков.
- Исходные spelling, абзацы, RTL и оба aliases сохраняются. Новый слой matcher/Room независимо создаёт NFC/whitespace/case-aware ключи и реализует ограниченный fuzzy; старые derived keys не являются источником истины.

## Интеграция Room v4 и остаток

Новая активная correction должна хранить оба исходных alias и их независимо пересчитанные ключи, перевод, языковую пару, `scopePackage`, `appLabel`, case/fuzzy/enabled-политику и метаданные времени/использования. Receipt должен ссылаться на `identity`, а не назначать старый `id` новому PK. При конфликте пользовательской записи нельзя молча заменять её импортом; нужны transaction/receipt/idempotence и явный отчёт.

Result возвращает `entries`, `issues`, `rowsSeen`, `truncated` и число `skipped`. Issues содержат1-based индекс строки и тип причины; `ROW_LIMIT` обозначает неполный просмотр, а не несуществующую импортированную строку. Дубликаты/конфликты в decoder не разрешаются: оба ряда сохраняются в preview для транзакционной проверки интегратором.

Helper подключён к `LegacyReader`: SQLite открывается read-only, колонки проверяются до проекции,
а `LegacyImporter` сохраняет новые PK и отдельные idempotence receipts. Оба aliases, приложение,
языки и `updatedAtMs` переходят в Room v4. Старые счётчики использования/createdAt остаются в
исходной базе и не становятся выдуманными метриками новой библиотеки. Строки длиннее нового лимита
100000 символов получают явный отчёт; читаемый перенос истории и исходная база сохраняются.

Публичный `translation_memory_enabled` читается отдельно. Старое `false` преобразуется в отключённые
импортированные записи. При недоступных/повреждённых настройках импорт также остаётся выключенным.
Подтверждённый прежний default `true` используется только при отсутствии файла/значения настройки.
Новые пользовательские записи и существующие исправления не заменяются импортом.

`LegacyCorrectionReaderTest` покрывает оба aliases, wildcard/auto, scopes, отсутствие выдуманных flags,
неизвестные поля без чтения значений, discarded derived fields, числовые/Unicode ограничения и лимиты.
`LegacyImportIntegrationTest` создаёт реальные SQLite-источники, проверяет активный recall по обоим
aliases, изоляцию приложения/языка, неизменность исходных байтов, повторный импорт, сохранение ручной
правки и старое выключенное состояние. `RulesMigrationTest` проверяет frozen v3→v4, транзакционный
rollback и новый независимый bounded fuzzy matcher. Реальные итоги запусков фиксируются в общем QA-отчёте.
